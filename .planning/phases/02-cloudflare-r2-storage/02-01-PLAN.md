<objective>
Build a production-grade Cloudflare R2 storage provider abstraction (`storageService.js`), presigned upload API (`/api/storage/presigned-url`), and direct browser-to-R2 upload helper.
</objective>

<execution_context>
- Cloudflare R2 is S3-compatible, requiring accountId, accessKeyId, secretAccessKey, and bucketName.
- Key patterns: `interviews/{interviewId}/video/{clipId}.mp4`, `interviews/{interviewId}/audio/{clipId}.wav`, `resumes/{userId}/{resumeId}.pdf`.
- Environment variables: `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_PUBLIC_DOMAIN`.
</execution_context>

<tasks>
<task id="1" type="auto">
  <name>Backend — Cloudflare R2 Storage Service Abstraction</name>
  <files>
    - backend/services/storageService.js
    - .env.example
  </files>
  <action>
    1. Create `backend/services/storageService.js`:
       - Initialize `S3Client` pointing to Cloudflare R2 endpoint `https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com`.
       - Check if credentials exist (`R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`).
       - Provide `getPresignedUploadUrl({ key, contentType, expiresIn })` using `PutObjectCommand` and `getSignedUrl`.
       - Provide `getPresignedDownloadUrl({ key, expiresIn })` using `GetObjectCommand` and `getSignedUrl`.
       - Provide `deleteObject({ key })` using `DeleteObjectCommand`.
       - Implement automatic fallback to local disk storage (`backend/uploads/`) if R2 credentials are not set in local dev environment.
    2. Add R2 credential variables to `.env.example`.
  </action>
  <acceptance_criteria>
    - `storageService.getPresignedUploadUrl` returns a signed URL string when configured.
    - Falls back cleanly to local storage without throwing unhandled exceptions if R2 credentials are missing in local dev.
  </acceptance_criteria>
</task>

<task id="2" type="auto">
  <name>Backend — Storage API Routes & Key Validation</name>
  <files>
    - backend/controllers/storageController.js
    - backend/routes/storage.js
    - backend/app.js
  </files>
  <action>
    1. Create `backend/controllers/storageController.js`:
       - `requestPresignedUrl(req, res)`:
         - Validates authenticated user (`req.user._id`).
         - Validates payload: `resourceType` ('video', 'audio', 'resume'), `interviewId` or `resumeId`, `contentType` ('video/webm', 'video/mp4', 'audio/webm', 'audio/wav', 'application/pdf').
         - Enforces ownership check (verifies `Session` belongs to `req.user._id` for interview media).
         - Generates structured key:
           - Video: `interviews/${interviewId}/video/${clipId}.webm`
           - Audio: `interviews/${interviewId}/audio/${clipId}.webm`
           - Resume: `resumes/${req.user._id}/${resumeId}.pdf`
         - Returns 200 OK with `{ uploadUrl, key, fileUrl }`.
    2. Create `backend/routes/storage.js` mounted at `/api/storage` with `POST /presigned-url` protected by `protect`.
    3. Mount `app.use('/api/storage', storageRoutes)` in `backend/app.js`.
  </action>
  <acceptance_criteria>
    - `POST /api/storage/presigned-url` returns 200 OK with uploadUrl and storage key for authorized requests.
    - Denies unauthorized attempts to request presigned upload URLs for sessions owned by other users.
  </acceptance_criteria>
</task>

<task id="3" type="auto">
  <name>Frontend — Direct R2 Upload Client Helper</name>
  <files>
    - frontend/src/api/storage.js
  </files>
  <action>
    1. Create `frontend/src/api/storage.js`:
       - `uploadDirectToR2({ blob, resourceType, interviewId, contentType })`:
         - Calls `POST /api/storage/presigned-url` to obtain presigned URL and key.
         - Performs direct HTTP PUT to `uploadUrl` with `headers: { 'Content-Type': contentType }`.
         - Returns `{ key, fileUrl }`.
  </action>
  <acceptance_criteria>
    - Frontend helper successfully requests presigned URL and completes upload without exposing R2 secret credentials.
  </acceptance_criteria>
</task>
</tasks>

- Node.js backend builds cleanly without errors.
