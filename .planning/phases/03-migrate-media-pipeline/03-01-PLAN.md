<objective>
Migrate the live interview media pipeline to upload video/audio clips directly to R2 object storage, ingest them into Python AI analysis microservices via `storageService`, track retryable job states, and clean up temporary clips post-analysis.
</objective>

<execution_context>
- Frontend currently records video/audio in `LiveInterviewPage.jsx` and calls `interviewApi.uploadAnswer`.
- Backend `answerController.js` and `analysisService.js` process uploads and dispatch BullMQ jobs.
- Target R2 key structure: `interviews/{interviewId}/video/{questionId}.webm` & `interviews/{interviewId}/audio/{questionId}.webm`.
</execution_context>

<tasks>
<task id="1" type="auto">
  <name>Frontend — Integrate Direct R2 Storage Upload in Live Interview Flow</name>
  <files>
    - frontend/src/pages/LiveInterviewPage.jsx
    - frontend/src/api/interview.js
  </files>
  <action>
    1. Update `uploadAnswer` in `frontend/src/api/interview.js` to utilize `storageApi.uploadDirectToR2`:
       - Request presigned URL for `resourceType: 'video'` with `interviewId` and `questionId`.
       - Execute direct upload to R2 (or fallback endpoint).
       - Send storage key / URL to `POST /api/sessions/:id/answers`.
    2. Update `handleUpload` in `LiveInterviewPage.jsx` to pass recording blob through R2 direct upload pipeline.
  </action>
  <acceptance_criteria>
    - Recorded video/audio clips are uploaded via `uploadDirectToR2` without blocking backend server memory.
    - `answer.videoUrl` stores R2 key/URL on the Session model.
  </acceptance_criteria>
</task>

<task id="2" type="auto">
  <name>Backend — R2 Ingestion & Retryable AI Job Processing</name>
  <files>
    - backend/services/analysisService.js
    - backend/controllers/answerController.js
  </files>
  <action>
    1. Update `analysisService.js`:
       - Create `resolveMediaStreamOrPath(keyOrUrl)` helper that fetches R2 storage object (or local file fallback) into a temporary buffer for AI inference.
       - Enforce retryable BullMQ job status flow (`pending` -> `processing` -> `completed` / `failed`).
       - Preserve partial results if one model succeeds while another fails.
       - Implement post-processing cleanup: remove temporary analysis buffer & call `storageService.deleteObject` for temporary clips if configured.
  </action>
  <acceptance_criteria>
    - `analysisService.js` successfully fetches R2 objects for Face & Voice analysis.
    - Processing states (`processing`, `completed`, `failed`) update atomically.
  </acceptance_criteria>
</task>
</tasks>
