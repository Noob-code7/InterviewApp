<objective>
Integrate `faster-whisper` Speech-To-Text engine into Python `voice-service` microservice to accurately transcribe full candidate answer audio and store transcripts in MongoDB.
</objective>

<execution_context>
- Candidate answer audio/video clips are stored in R2 and ingested by `voice-service` at `http://127.0.0.1:8002/analyze`.
- `Session` model schema contains `voiceAnalysis.transcript`.
- Microservice deployment uses Python FastAPI with `faster-whisper` (`base.en` / `small.en` int8 quantized).
</execution_context>

<tasks>
<task id="1" type="auto">
  <name>AI Microservice — Integrate Faster-Whisper in Voice Service</name>
  <files>
    - ai-services/voice-service/main.py
    - ai-services/voice-service/requirements.txt
  </files>
  <action>
    1. Update `ai-services/voice-service/requirements.txt` to include `faster-whisper`.
    2. Update `ai-services/voice-service/main.py`:
       - Load `faster-whisper` model (`WhisperModel("base.en", device="cpu", compute_type="int8")`) on startup.
       - Implement `transcribe_audio(audio_path)` function:
         - Extract speech segments using `whisper_model.transcribe(audio_path, beam_size=5, language="en")`.
         - Handle silence, empty audio, background noise, and non-speech artifacts.
       - Update `/analyze` endpoint to execute `faster-whisper` transcription and assign real transcript to `VoiceAnalysisResult.transcript`.
       - Add explicit `/transcribe` endpoint accepting audio file uploads.
  </action>
  <acceptance_criteria>
    - `POST /analyze` in `voice-service` returns real transcribed text from candidate answer audio.
    - Handles silence and empty audio without throwing unhandled 500 exceptions.
  </acceptance_criteria>
</task>
